## 1. 完成范围

### 1.1 价税分离

- 销售订单、销售发货、采购订单、采购收货支持 `price_includes_tax`，默认含税。
- 行级税率：默认取物料税率，可手工覆盖；保存 `tax_rate` 快照。
- 行金额：不含税金额、税额、含税金额。
- 表头金额：不含税合计、税额合计、含税总额。
- 共享 `taxcalc` 包统一含税/不含税计算，行级四舍五入到 4 位。

### 1.2 自动凭证

- 销售发货：
  - 借应收账款（含税总额）
  - 贷主营业务收入（不含税）
  - 贷应交税费-销项税额
  - 销售成本分录不变
- 采购收货：
  - 借库存商品（不含税）
  - 借应交税费-进项税额
  - 贷应付账款（含税总额）
- 税额为 0 时不生成税务行。
- 收付款仍按含税总额核销。

### 1.3 发票

- 应收/应付发票增加净额、税额、增值税发票号、类型、开票日期、开票状态、购销方税号。
- 开票状态：`pending → issued → void`。
- `POST /finance/invoices/:id/issue` 开票。
- `POST /finance/invoices/:id/void` 作废。
- 发票号租户内唯一；重复开票返回 `409 VAT_INVOICE_NO_DUPLICATE`。
- 状态不允许时返回 `409 INVOICE_STATUS`。
- 开票/作废不生成凭证，税额已在发货/收货确认。

### 1.4 增值税汇总

- `GET /finance/reports/vat-summary`：按月销项税、进项税、应纳税额及合计。
- 数据来自 `222101`/`222102` 已过账或已反过账凭证，应用组织数据范围。
- 前端“财务报表”增加“增值税汇总” Tab。

### 1.5 前端

- 销售/采购订单：含税开关、税率选择、净额/税额/含税金额和合计。
- 订单/发货详情展示税务字段。
- 应收应付列表：开票状态、增值税发票号、净额、税额、开票/作废操作。
- 发票详情展示完整税务和开票信息。
- 财务报表增加增值税汇总。

## 2. 数据库变更

迁移 `000017_tax_invoice`：

- 销售/采购订单、发货、收货头：`price_includes_tax`、`net_amount`、`tax_amount`；发货/收货增加 `total_amount`。
- 单据行：`tax_rate_id`、`tax_rate`、`tax_amount`、`gross_amount`；`amount` 改为不含税金额。
- 应收/应付发票：`net_amount`、`tax_amount`、`vat_invoice_no`、`vat_invoice_type`、`vat_invoice_date`、`vat_invoice_status`、`buyer_tax_no`、`seller_tax_no`。
- 历史数据回填：净额=原金额、税额=0、含税金额=原金额、开票状态 `pending`。
- 税率外键、发票状态/类型检查、增值税发票号部分唯一索引。
- 新增 `222101` 进项税额、`222102` 销项税额，`2221` 改为非末级。
- 新增 `input_vat`/`output_vat` 科目映射。
- 新增 `finance.invoice.write` 权限并授予 admin 角色。

## 5. 代码审核

### 5.1 审核方式

独立代码审核子代理，审查范围 `0ef06ad..16dc062`，覆盖税额计算、单据金额语义、自动凭证、发票状态、VAT 汇总、迁移、前端和测试。

### 5.2 审核结论

初次审核结论：**Ready to merge: With fixes**。

- **Critical 1 项**：Stage 3E 迁移新增发货/收货表头 `total_amount` 默认 0，历史表头无法用表头旧字段回填，导致历史发货/收货净额和含税总额为 0。
- **Important**：采购收货响应缺少含税总额；税率主数据允许 `rate >= 1`；回滚迁移未恢复行金额的含税语义；前端切换物料可能保留旧税率；测试覆盖不足。
- 审核确认税额计算、含税/不含税公式、自动凭证借贷平衡、库存净成本、发票状态机、VAT 汇总符号/范围/反过账处理整体正确。

修复后结论：**Ready to merge: Yes**。Critical 已修复并回归，主要 Important 项已修复。

### 5.3 已修复问题

- 新增迁移 `000018_repair_tax_headers`：按发货/收货行汇总回填历史表头净额、税额和含税总额；开发库验证无剩余零表头。
- 采购收货响应增加 `total_amount`，SDK/OpenAPI 同步。
- 税率主数据拒绝 `rate < 0` 或 `rate >= 1`，避免创建后无法用于订单。
- 前端切换物料时始终重置为物料默认税率（无默认则清空）。
- `000017` 回滚迁移在删除 `gross_amount` 前把行 `amount` 恢复为含税金额。
- 补充采购含税收货、发票状态/发票号过滤、作废 403、税率非法值、VAT 汇总精确增量测试。
- 采购进项税凭证行增加供应商辅助核算。

### 5.4 未修复/后续处理

- 历史库存余额和流水仍按 Stage 3E 之前的含税成本计价，新收货按不含税成本，旧库存消耗前成本口径会混合；需要一次性库存重估或明确消耗策略。
- 销项税在发货时确认、作废发票不冲销税额、进项税在收货时确认而未区分认证状态，属于已记录的业务假设。
- 部分发货/收货按行独立四舍五入，极端小数单价下多次部分发货合计可能与订单总额有 0.0001 差异。
- 前端税额预览仍使用 JavaScript Number，后端 decimal 为权威。
- OpenAPI 中 `vat_invoice_date` 在未开票时返回空字符串，而非 null；生成客户端需按字符串处理。
- Demo 尚未提供已开票发票和明确的不含税订单样例。

## 6. 已知限制

- 税额在发货/收货时确认，不按开票时点确认；未开票暂估、发票与收入跨期差异未实现。
- 历史库存余额和流水仍按 Stage 3E 之前的含税成本计价，新收货按不含税成本；旧库存消耗前成本口径会混合，需要一次性重估或明确消耗策略。
- 销项税在发货时确认、作废发票不冲销税额、进项税在收货时确认而未区分认证状态，属于当前业务假设。
- 发票作废不回冲收入或税额；红字发票和完整红冲流程后置。
- 发票为内部台账，未对接税控系统、电子发票或申报表。
- 采购进项税在收货时确认，未区分“待认证/已认证”进项税。
- 一张应收/应付发票只记录一个增值税发票号和票种；混合税率税额按合计记录。
- 多币种、汇率、汇兑损益未实现；当前仍为单一本位币金额。
- 现金流量表未实现。
- 项目仍为自由文本辅助核算，无项目主数据。
- 报表为实时聚合，大数据量需要余额表/物化视图。
- 自动化测试覆盖主要路径，缺少并发开票、事务故障注入和真实浏览器 E2E。
- 迁移回滚不清理已生成税务凭证和已开票数据，回滚前需评估。
