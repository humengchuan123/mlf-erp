## 1. 完成范围

### 1.1 直接法现金流量表

- 新增 `GET /api/v1/finance/reports/cash-flow`，按日期区间返回直接法主表。
- 经营活动、投资活动、筹资活动分别输出现金流入、现金流出和净额。
- 返回现金净增加额、期初现金和期末现金。
- 金额均为本位币 CNY 字符串，固定 4 位小数；未发生项目返回 `0.0000`。

### 1.2 标准现金流项目与科目映射

- 定义 18 个标准现金流项目：
  - 经营活动流入 3 项、流出 4 项。
  - 投资活动流入 2 项、流出 3 项。
  - 筹资活动流入 3 项、流出 3 项。
- 现金/银行科目取 `cash`、`bank` 映射，并按编码前 4 位根归一化；映射缺失时回退 `1001`、`1002`。
- 非现金对方科目按标准科目编码根自动归类，覆盖应收、应付、存货、职工薪酬、税费、收入、成本费用、固定资产/无形资产、交易性金融资产、长期股权投资、借款、实收资本和利润分配等。
- 无法识别或无对方科目的现金分录进入“其他经营活动现金流”，并标记为未分类。

### 1.3 内部现金互转与未分类明细

- 现金/银行科目之间的互转不进入任何现金流项目，也不计入净增加额。
- 未分类现金凭证返回：
  - 凭证 ID、凭证号、凭证日期。
  - 流入/流出方向。
  - 金额。
  - 原因（无对方科目或未识别科目编码）。
- 前端增加未分类明细表，并将 `inflow`/`outflow` 显示为“流入”/“流出”。

### 1.4 间接法附表

- 返回净利润、非付现费用、经营性应收增加、存货增加、经营性应付增加、应交税费增加、应付职工薪酬增加。
- 输出间接法经营活动现金流量净额、直接法经营活动现金流量净额和差额。
- 差额不为零时前端显示警示提示；是否显示使用数值比较，避免字符串格式差异造成误判。

### 1.5 API、SDK、OpenAPI 和前端

- SDK 新增 `CashFlowStatement` 类型和 `glApi.reports.cashFlow` 方法。
- OpenAPI 增加路径、请求参数和响应 Schema，版本更新为 `0.8.0`。
- “财务报表”页面新增“现金流量表”页签：日期区间、三类活动流入/流出/净额、间接法、未分类明细和加载状态。
- 页面描述更新为“科目余额表、明细账、资产负债表、利润表、现金流量表、辅助余额表和增值税汇总。”
- 前端完整度检查增加 `cashRange`、`loadCashFlow`、`name="cash"` 等断言。

### 1.6 测试与 CI

## 2. 数据与算法

### 2.1 现金科目范围

- 从 `gl_account_mappings` 读取 `cash`、`bank` 映射。
- 每个映射同时加入精确编码和 4 位数字根，例如 `1002.01` 同时支持 `1002.01` 和 `1002`。
- `cash` 或 `bank` 映射缺失时分别回退 `1001`、`1002`。
- 现金余额、凭证现金行识别和期初/期末余额使用同一套根语义。

### 2.2 凭证取数与分组

- 只统计 `posted` 和 `reversed` 凭证。
- 凭证日期在 `start_date` 至 `end_date` 区间内。
- 按 `tenant_id` 隔离，并应用组织数据范围。
- 查询在只读、`RepeatableRead` 事务内执行，保证直接法、现金余额和间接法读取同一快照。
- 按凭证聚合分录，再逐张凭证分摊和归类。

### 2.3 直接法分摊

1. 现金流入 = 现金/银行科目借方合计；现金流出 = 现金/银行科目贷方合计。
2. 可归类流入 = `min(现金流入, 非现金贷方合计)`；可归类流出 = `min(现金流出, 非现金借方合计)`。
3. 无法匹配的流入/流出中，相等部分视为现金/银行内部互转并忽略；剩余部分进入其他经营活动现金流并标记未分类。
4. 可归类流入按非现金贷方分录金额比例分摊；可归类流出按非现金借方分录金额比例分摊。
5. 每条分摊结果按对方科目编码根匹配标准现金流项目。
6. 按项目汇总，计算三类活动净额和现金净增加额。

### 2.4 舍入与尾差

- 非最后一条分摊金额向下截断到 4 位小数（`Truncate(4)`）。
- 最后一条分摊金额取剩余金额并四舍五入到 4 位（`Round(4)`），吸收尾差。
- 项目汇总、活动净额、现金净增加额、期初/期末现金和间接法各项统一四舍五入到 4 位。
- 分摊金额为零的分录不写入汇总和未分类明细。

### 2.5 期初/期末现金

- 期初现金 = 起始日前一日现金/银行科目累计余额。
- 期末现金 = 截止日现金/银行科目累计余额。
- 余额 = 借方累计 - 贷方累计，应用相同的组织数据范围和凭证状态口径。
- 现金净增加额 = 经营净额 + 投资净额 + 筹资净额。

### 2.6 间接法公式

```text
净利润
+ 非付现费用
- 经营性应收项目增加
- 存货增加
+ 经营性应付项目增加
+ 应交税费增加
+ 应付职工薪酬增加
= 间接法经营活动现金流量净额
差额 = 间接法经营活动现金流量净额 - 直接法经营活动现金流量净额
```

- 净利润复用利润表区间口径，排除期间结转和年度结转凭证。
- 非付现费用读取 `non_cash_expense` 映射；映射缺失或期间无发生额时为 0。
- 经营性应收取 `1122`，存货取 `1405`，经营性应付取 `2202`，应交税费取 `2221`，应付职工薪酬取 `2211`。
- 增加额 = 截止日余额 - 起始日前一日余额；资产类按借方净额，负债类按贷方净额。
- 间接法为简化调节表，差额仅用于提示分类或映射缺口，不自动生成调整分录。

## 3. API 清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/finance/reports/cash-flow` | `finance.report.read` | 现金流量表 |

查询参数：

- `start_date`：可选，日期格式 `YYYY-MM-DD`，默认当月 1 日。
- `end_date`：可选，日期格式 `YYYY-MM-DD`，默认当天。

行为：

- `start_date` 晚于 `end_date` 或日期格式非法时返回 400 `BAD_REQUEST`。
- 未登录返回 401 `UNAUTHORIZED`。
- 缺少权限返回 403 `FORBIDDEN`。
- 报表应用组织数据范围。
- 响应包含 `operating`、`investing`、`financing`、`net_increase`、`opening_cash`、`closing_cash`、`unclassified` 和 `indirect`。

## 6. 已知限制

- 科目归属按 4 位数字根匹配：同一根下的兄弟子科目共享同一现金流项目，无法按子科目细分；映射表也不提供租户级现金流项目配置。
- 科目编码必须以数字开头且前 4 位可用于匹配；非数字编码或自定义编码无法自动归类，会进入其他经营并标记未分类（现金精确编码映射除外）。
- 复合凭证按对方科目金额比例分摊，复杂手工凭证的分摊结果可能与人工判断不同；现金流入/流出同时存在时按最小匹配额处理，极端凭证可能产生未分类尾差。
- 非付现费用只支持单个 `non_cash_expense` 映射，且没有维护页面/API；标准科目表没有折旧、摊销科目时显示 0。
- 不提供凭证行手工指定现金流项目，也不支持项目级覆盖。
- 现金等价物仅包含 `cash`、`bank` 映射，未支持短期投资等现金等价物配置。
- 银行/现金外币账户不做期末重估，不支持跨币种现金流分摊或跨币种核销。
- 间接法为简化调节表，只覆盖设计中的标准项目；差额仅提示，不自动生成调整分录。
- 现金流量表为实时聚合，大数据量下需要余额表、物化视图或预计算。
- API 测试写入本地开发库并消耗一个干净年度；不得在需要保留年度的数据库上重复执行，完整回归请使用干净数据库。
- 自动化测试覆盖主要路径，尚缺浏览器 E2E、并发关账/过账和事务故障注入。
