## 1. 完成范围

### 1.1 汇率管理

- 新增汇率表 `finance_exchange_rates`，按币种和生效日期维护。
- CNY 固定汇率 1，不存表。
- 汇率精度 8 位，外币 1 单位 = X CNY。
- API：列表、最近汇率、新增/更新。
- 前端新增“汇率管理”页面、路由和菜单。

### 1.2 外币单据

- 销售/采购订单、发货、收货、应收应付发票、收付款保存：
  - 原币金额
  - `exchange_rate` 汇率快照
  - CNY 本位币金额
- 单据默认取单据日期最近汇率，可手工覆盖。
- 订单行、发货行、收货行保存本位币净额/税额/含税额。
- 历史数据回填：汇率 1、本位币金额等于原币金额。该假设只对历史 CNY 单据成立；生产升级前必须审计历史外币单据（见 6. 已知限制）。

### 1.3 自动凭证

- 销售发货：借应收（本位币含税）/ 贷收入（本位币不含税）/ 贷销项税（本位币）。
- 采购收货：借库存（本位币不含税）/ 借进项税（本位币）/ 贷应付（本位币含税）。
- 收付款：按本位币金额。
- 原币金额不进入总账。

### 1.4 已实现汇兑损益

- 收付款创建时按付款日汇率折算本位币。
- 核销时计算 `fx_diff = 核销原币 × (付款汇率 - 发票汇率)`。
- 应收/应付分别生成 `fx_settlement` 凭证：
  - 收益贷记 `660302 汇兑收益`。
  - 损失借记 `660301 汇兑损失`。
- 支持同一收付款核销多张不同汇率发票。
- 追加核销按增量生成汇兑损益记录和凭证。

### 1.5 期末重估

- 关账事务内在损益结转前重估未核销外币应收应付。
- 目标本位币余额 = 未核销原币 × 期末汇率。
- 当前账面本位币余额 = 发票本位币总额 - 已核销本位币（上期重估已在次期反向，不再叠加）。
- 差额生成 `fx_revaluation` 凭证。
- 次期初生成借贷方向相反的 `fx_revaluation_reversal` 反向凭证。
- `base_revalued_amount` 保存本期间重估调整额，下期关账时替换而非累计；零调整时清零。
- `gl_fx_revaluations` 记录期间、发票、原币余额、汇率、调整额和凭证。
- 反关账生成 `fx_revaluation_reopen` 和次期 `fx_revaluation_reversal_reopen`，回退本期间重估。
- 次期已关账时拒绝本期关账/反关账。

### 1.6 科目

- `660301 汇兑损失`（费用类、借方）。
- `660302 汇兑收益`（费用类、贷方）。
- `6603 财务费用` 改为非末级。
- 映射：`fx_loss=660301`、`fx_gain=660302`。

## 5. 代码审核

### 5.1 审核方式

独立代码审核子代理，审查范围 `83f35bd..2ff9414`，覆盖汇率与本位币金额、自动凭证、已实现汇兑损益、期末重估、反关账、迁移、前端和测试。

### 5.2 审核结论

初次审核结论：**Ready to merge: No**。

- **Critical 1**：重估反向凭证的 `for _, line := range lines` 修改的是副本，所有 `fx_revaluation_reversal`、`fx_revaluation_reopen` 和 `fx_revaluation_reversal_reopen` 凭证借贷方向没有反转，导致次期和反关账重复确认资产/损益。
- **Critical 2**：`base_revalued_amount` 在下期反向凭证生成后未清零，下期关账把上期重估继续计入账面金额，连续关账时汇兑调整逐月偏小。
- **Important**：销售/采购/GL 缺失汇率返回 500；采购库存流水金额仍为原币；Demo 历史应付本位币为 0；订单改期/改币种可能复用旧汇率；收付款币种硬编码且订单页币种权限会阻塞选项加载；测试未覆盖反向方向和连续关账。
- 审核确认汇率快照、行/表头本位币金额、自动凭证、核销锁定和方向、重估事务边界、迁移和前端整体结构正确。

修复后结论：**Ready to merge: Yes**。两个 Critical 已修复并补充回归测试；主要 Important 项已修复。

### 5.3 已修复问题

- **Critical 1**：`fxRevaluationLines` 改为按下标反转借贷方向；新增 `period_repository_test.go` 单元测试，并在 Stage 3F API 测试中逐行断言重估、次期反向、反关账和次期反向撤销的借贷方向。
- **Critical 2**：重估账面金额改为 `base_total - base_paid`，不再把上期重估加入；`base_revalued_amount` 按本期间调整额替换，零调整清零，发票全额核销时清零。新增连续 1/2/3 月关账测试，断言 2 月调整 +20、3 月调整 0。
- 销售、采购和 GL 处理器补齐 `EXCHANGE_RATE_NOT_FOUND` / `INVALID_EXCHANGE_RATE` 400 映射。
- 采购收货库存流水金额改记本位币不含税金额，与 CNY 单位成本一致。
- Demo 历史应付补写 `exchange_rate`、本位币净额/税额/总额和已核销。
- 订单编辑时改日期或币种会清空手工汇率并重新取数；后端不再隐式保留旧汇率。
- 销售/采购订单页币种选项独立加载，缺少 `masterdata.currency.read` 时回退 CNY/USD；收付款页改为动态币种列表。
- `latest exchange rate` 未传日期时返回实际生效日期；手工覆盖汇率统一四舍五入到 8 位。
- Stage 3F 测试从 3 个扩展到 7 个，覆盖自动取汇率、含税本位币拆分、应收/应付汇兑损失、重估反向方向和连续期间关账；干净年份扫描扩展并在耗尽时失败而不是跳过。

### 5.4 未修复/后续处理

- 历史外币单据按汇率 1 回填的风险未自动修复：生产升级前需执行审计 SQL，确认 `currency <> 'CNY'` 的历史订单/发票/收付款；如存在，需补历史汇率或人工修正本位币金额后再关账。
- 银行/现金外币账户、预收预付不重估；不支持跨币种核销。
- 重估是租户级，但重估凭证使用关账用户所属组织；其他组织的组织级资产负债表不会包含其应收应付重估。
- 已实现汇兑损益凭证日期使用付款日期而非实际核销日期；付款期间已关账时，后续核销会被拒绝。
- 核销按每次分摊四舍五入，极端汇率/多次分摊可能留下 0.0001 本位币尾差。
- 核销接口没有幂等键，重试可能重复生成分摊和汇兑损益凭证。
- 未补 `finance_fx_settlements.voucher_id` 等新增外键、汇率 `updated_by` 审计和分配置汇总优化。
- 自动化测试仍缺少并发核销/关账、事务故障注入和浏览器 E2E。

## 6. 已知限制

- 历史外币单据迁移按汇率 1 回填；生产升级前必须审计历史 `currency <> 'CNY'` 单据，必要时补历史汇率或人工修正。
- 银行/现金外币账户不做期末重估。
- 不支持跨币种直接核销；收付款必须与发票同币种。
- 只有 CNY 一个本位币，不支持多本位币/合并报表折算。
- 汇率表为手工维护，未接外部汇率源或汇率类型（买入/卖出/中间价）；API 不校验币种是否为主数据启用币种。
- 期末重估只覆盖未核销应收应付，不覆盖预收预付、外币银行/现金。
- 重估按发票逐张计算，汇总凭证行数可能较多；后续可按客商/币种聚合优化。
- 重估是租户级，重估凭证归属关账用户组织；其他组织的组织级资产负债表不会包含其应收应付重估。
- 已实现汇兑损益凭证使用付款日期；付款期间已关账时后续核销会被拒绝。
- 核销按每次分摊四舍五入，多次分摊可能产生 0.0001 本位币尾差；核销接口无幂等键。
- 汇兑损益凭证在核销/关账事务内生成，若科目映射缺失会导致核销/关账失败。
- 历史库存成本仍可能存在含税/不含税口径混合（Stage 3E 已记录）。
- 报表为实时聚合，大数据量需要余额表/物化视图。
- 自动化测试覆盖主要路径，缺少并发核销、并发关账、事务故障注入和浏览器 E2E。
- 迁移回滚不清理已生成汇率、汇兑损益凭证和重估记录，回滚前需评估。
