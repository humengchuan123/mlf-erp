## 1. 完成范围

### 1.1 期末损益结转

- 关账时自动汇总本期收入/费用科目余额，生成损益结转凭证。
- 收入类科目借方冲平，费用类科目贷方冲平，轧差计入本年利润 `4103`。
- 结转凭证 `voucher_type=period_close`，已过账，来源为关账记录。
- 本期无损益余额时不生成结转凭证，仅写关账记录。
- 期间存在草稿凭证时禁止关账；关账后禁止新增/过账凭证。

### 1.2 反关账与再次关账

- 反关账生成同期间反向结转凭证 `voucher_type=period_close_reversal`。
- 关账记录标记 `reopened`，期间恢复 `open`。
- 再次关账生成新的关账记录和新结转凭证；旧结转与反向凭证在报表中抵消。
- 反关账事务内锁定期间行，避免与过账并发冲突。

### 1.3 年度期间与年度结转

- `POST /finance/periods/ensure` 一次创建指定年度 12 个会计期间。
- 年度结转要求该年度 12 个期间全部 `closed`，且每个已关账期间都有对应的关账记录。
- 年度结转按年度顺序执行：上一年度有期间但尚未结转时拒绝，已存在更晚年度结转时拒绝。
- 在次年 1 月 1 日生成 `4103 → 4104` 年度结转凭证：
  - 盈利：借本年利润 `4103` / 贷利润分配 `4104`。
  - 亏损：借利润分配 `4104` / 贷本年利润 `4103`。
  - 余额为零时只写年度关账记录，不生成凭证。
- 年度结转后该年度期间禁止反关账；同一租户同一年度只能结转一次，不提供反结转。
- `GET /finance/years/:year/close` 返回年度结转状态和结转凭证号。

### 1.4 辅助核算

- 凭证行增加项目编码 `project_code`，与已有客商 `partner_id`、部门 `department_id` 组成辅助核算。
- `GET /finance/dimensions` 返回启用客商和部门选项。
- 自动凭证带入客商；部门/项目暂不自动带入，可手工录入。
- 辅助余额表按客商/部门/项目 + 科目分组，展示期初、本期借方、本期贷方、期末。
- 项目当前使用轻量文本编码，后续再接项目主数据。

### 1.5 报表口径

- 科目余额表、资产负债表、明细账：包含损益结转、反结转、年度结转凭证。
- 利润表、辅助余额表：排除 `period_close`、`period_close_reversal`、`year_close`，保持经营口径。
- 所有报表严格应用组织数据范围。结转凭证归属执行关账的用户组织：
  - 公司范围用户可见结转凭证，关账后损益归零、4103 体现利润。
  - 部门范围用户看不到公司级结转凭证，报表保持本部门未结转经营口径，不会泄露全公司损益。
- 资产负债表权益包含 `4103`/`4104`，未结转利润仍按收入 - 费用计算。

### 1.6 前端

- 会计凭证：分录行增加客商、部门、项目辅助字段。
- 会计期间：增加“创建年度期间”“年度结转”；关账/反关账提示说明会生成结转/反结转凭证。
- 财务报表：新增“辅助余额表” Tab，可按维度、科目和日期范围查询。
- SDK、OpenAPI、前端完整度检查同步更新。

## 2. 数据库变更

迁移 `000015_period_close_auxiliary`：

- `erp.gl_voucher_lines.project_code text NOT NULL DEFAULT ''`。
- 新增 `erp.gl_period_closes`：关账记录、结转凭证、反结转凭证、状态、操作人/时间。
- 新增 `erp.gl_year_closes`：年度关账记录，唯一约束 `(tenant_id, year)`。
- 新增科目映射：`profit=4103`、`retained_earnings=4104`。
- 索引：关账记录按期间倒序、年度关账、凭证行项目编码。

关键约束：

- 关账记录通过 `(tenant_id, period_id)` 关联期间，通过 `(tenant_id, voucher_id)` 关联结转凭证和反结转凭证。
- 关账状态仅允许 `closed`/`reopened`，年度关账状态仅允许 `closed`。
- 迁移为现有租户补写 `4103`/`4104` 映射；`down` 迁移删除表、索引、字段，保留可能已存在的科目映射。

迁移 `000016_period_close_integrity`：

- 关账记录增加部分唯一索引：同一期间只能有一条 `closed` 关账记录。
- 凭证行客商/部门增加租户级外键，项目编码增加 64 字符长度约束（`NOT VALID`，新数据强制执行）。
- 删除与年度关账唯一约束重复的索引。

## 3. API 清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/finance/dimensions` | `finance.voucher.read` | 客商/部门辅助选项 |
| GET | `/api/v1/finance/reports/auxiliary-balance` | `finance.report.read` | 辅助余额表 |
| POST | `/api/v1/finance/periods/ensure` | `finance.period.close` | 创建年度 12 个期间 |
| POST | `/api/v1/finance/periods/:id/close` | `finance.period.close` | 期末结转并关账 |
| POST | `/api/v1/finance/periods/:id/reopen` | `finance.period.close` | 反关账并生成反结转凭证 |
| POST | `/api/v1/finance/years/:year/close` | `finance.period.close` | 年度结转 4103 → 4104 |
| GET | `/api/v1/finance/years/:year/close` | `finance.period.read` | 年度结转状态和凭证号 |

- 金额仍使用字符串传输，日期使用 `YYYY-MM-DD`。
- 年度未全部关账返回 `409 YEAR_NOT_CLOSED`；年度已结转返回 `409 YEAR_CLOSED`。
- 年度顺序不合法返回 `409 YEAR_OUT_OF_ORDER`；已关账期间缺少关账记录返回 `409 PERIOD_CLOSE_MISSING`。
- OpenAPI 版本更新为 `0.5.0`，补充新接口、辅助字段和辅助余额模型。

## 5. 代码审核

### 5.1 审核方式

独立代码审核子代理，审查范围 `1a79842..3dad52c`，覆盖期末结转/反关账/年度结转事务、报表口径、数据权限、辅助余额 SQL、迁移、前端和测试。

### 5.2 审核结论

初次审核结论：**Ready to merge: No**。

- **Critical 4 项**：
  1. 年度结转余额查询排除所有 `year_close` 凭证，导致以前年度已结转利润在后续年度被重复结转。
  2. 已年度结转的年度仍可反关账/重新关账，年度结转不可逆但年度数据仍可修改。
  3. Stage 3D 之前关账的期间没有关账记录和结转凭证，年度结转可能把不正确的年度永久锁定。
  4. 报表对结转凭证放行数据范围，部门范围用户可见全公司收入、费用和 4103，形成数据泄露。
- **Important**：总账期初与分录范围口径不一致、无损益关账不写记录、年度结转并发不安全、年度结转未做顺序校验、部门维度包含公司组织、手工反过账丢失项目编码、OpenAPI 凭证类型未同步、前端无法查看结转凭证/辅助字段、年度结转缺少状态提示、关键测试缺失、辅助核算输入校验不足。
- 审核同时确认关账事务、借贷方向、反结转对称性、辅助余额参数化 SQL、迁移结构和 API 权限整体正确。

审核修复后结论：**Ready to merge: Yes**。Critical 4 项和主要 Important 项已修复并回归，剩余项记录为已知限制。

### 5.3 已修复问题

- **Critical 1：年度结转重复计算以前年度利润**
  - 年度结转余额查询不再排除 `year_close` 凭证，以前年度结转会正确冲减 4103。
  - 新增三年连续结转测试，断言每年只结转当年利润，4104 增量等于当年利润。
- **Critical 2：已结转年度仍可修改**
  - 期间关账/反关账增加年度结转检查，已结转年度返回 `409 YEAR_CLOSED`。
  - 年度结转按年度顺序执行，上一年度未结转或存在更晚年度结转时返回 `409 YEAR_OUT_OF_ORDER`。
- **Critical 3：Stage 3D 之前关账的期间没有结转记录**
  - 年度结转要求每个已关账期间都有 `closed` 关账记录，否则返回 `409 PERIOD_CLOSE_MISSING`。
  - 无损益期间也写关账记录（凭证为空），反关账会正确把记录标记 `reopened`。
  - 新增部分唯一索引，保证同一期间只有一条 `closed` 关账记录。
  - 手动验证删除关账记录后年度结转被拦截，恢复记录后可继续。
- **Critical 4：报表数据范围泄露**
  - 移除结转凭证的数据范围豁免，所有报表统一使用组织数据范围。
  - 新增部门/公司范围测试：部门用户 4103 为 0 且试算平衡，公司用户可见结转凭证。
  - 结转凭证归属执行关账的用户组织，不再宣称租户级可见。
- **Important**
  - 总账期初和分录统一使用同一套数据范围。
  - 年度结转锁定该年度全部期间行，避免并发反关账；重复年度结转稳定返回 `YEAR_CLOSED`。
  - 部门维度只返回 `type='dept'`，辅助余额部门维度排除公司组织。
  - 手工凭证反过账复制 `project_code`，新增项目辅助余额归零测试。
  - OpenAPI 补充 `period_close`、`period_close_reversal`、`year_close` 和年度结转状态接口。
  - 前端补充结转类型标签、锁定凭证详情辅助字段、年度结转状态提示和重复操作禁用。
  - 辅助核算增加客商/部门 UUID 校验、项目编码 64 字符限制，并增加数据库外键和长度约束。
  - 辅助余额增加结束日期上界，避免未来日期产生零行。
  - 新增 401/403、非法 UUID、零余额年度、年度顺序、期初余额等测试。
  - CI Web 任务增加前端完整度检查。

### 5.4 未修复/后续处理

- 凭证号在关账/年度结转校验前生成，失败时可能产生号码缺口；不影响凭证唯一性和账务正确性，后续可改为事务内按需取号。
- 年度结转仍为单向，不提供受控的年度反结转；调整需在后续年度做调整凭证。
- 结转凭证仍按执行关账用户的组织归属，多组织租户尚未实现按组织分别关账/结转。
- 项目仍是自由文本，无项目主数据和更细的辅助核算明细账。
- 报表为实时聚合，大数据量需要余额表/物化视图。
- 缺少并发关账/过账、事务故障注入和真实浏览器 E2E 测试。
- 迁移 `000015` 回滚不会清理已生成的结转凭证和已关账期间，回滚到 Stage 3C 前需要评估这些数据。

## 6. 已知限制

- 未实现现金流量表、税务/发票、价税分离、多币种/汇率。
- 年度结转单向，不提供反结转；反结转需后续单独设计。
- 年度结转后该年度期间禁止反关账；如需调整，只能在后续年度做调整凭证。
- Stage 3D 之前关账的期间需要先反关账、重新关账，补齐关账记录后才能年度结转。
- 结转凭证按执行关账用户的组织归属；部门范围用户看到本部门未结转经营口径，不包含公司级结转凭证。
- 项目为自由文本编码，无项目主数据和编码校验；部门/项目暂不随业务单据自动带入。
- 辅助余额表按凭证行辅助字段汇总，未覆盖存货、往来账龄等更细维度。
- 报表为实时聚合，大数据量需要余额表/物化视图优化。
- 自动凭证不允许直接反过账，需走业务反向流程；业务退货/反核销仍未实现。
- 前端金额展示/预填仍使用 JavaScript `Number`，后端金额计算是权威的。
- 自动化测试覆盖主要路径，缺少并发关账/过账、事务故障注入、真实浏览器 E2E。
- 凭证号在失败操作时可能产生缺口，不影响唯一性和账务正确性。
- 新租户开户仍需复制标准科目、映射、期间和编码规则。
